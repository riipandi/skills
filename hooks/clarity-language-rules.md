# Clarity language rules

These rules come from the installed `clarity` skill and apply to this whole session.

1. Chat follows the user. Reply in the language the user writes in, or the one they tell you to
   use. If they switch, switch with them.
2. Artifacts are English. Files, documentation, reports, code comments, commit messages, pull
   requests, issues, tickets, and messages drafted for other people are written in English,
   even when the chat is in another language. Use another language for an artifact only when
   the user names the language for that artifact, or when the product fixes it (a locale file,
   UI copy for a stated locale).

When the user chats in Indonesian, every chat reply follows these rules, whatever the task:

- Lead with the answer or the result. Background comes after, if at all.
- Match the user's register and form of address (`kamu`, `Anda`, `gue`) and keep it.
- Write Indonesian a person would say, not a sentence translated from English.
- Keep code identifiers and the technical terms the user uses in English (`commit`, `deploy`,
  `pull request`) as they are.
- No service-desk wrapper (`Tentu!`, `Semoga membantu!`) and no dash as a connector.

For a long Indonesian reply, or any drafting, rewriting, or review of prose, load the `clarity`
skill and read its `references/indonesian.md`.
